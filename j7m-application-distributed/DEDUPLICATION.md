# Managed durable invocation deduplication

`ManagedDeduplicationPolicy` adapts `@Deduplicated` and one `@IdempotencyKey String` parameter to the existing D12 `DeduplicatedRpc`. It is a trusted host-installed `ManagedInvocationPolicy`, not an application-discovered backend. The host supplies a finite named `Registration` containing an authenticated tenant-bound backend, a `ManagedPayloadCodec`, retention and an UNKNOWN-only cleanup budget. Registrations borrow the backend and codec. Closing the binding rejects new calls without deleting durable identities.

The fixed REPLAY phase follows SECURITY, OBSERVATION, ADMISSION and OWNERSHIP and precedes TRANSACTION and APPLICATION. Every replay passes authorization again. The host pipeline must actually support result finalizers; legacy synchronous continuations fail closed. Named policies, a single consistent key index, supported declared codec types and the complete interface/implementation lineage validate before application construction. OneWay plus deduplication is unsupported. Async methods use their concrete logical payload type, not a serialized future.

The durable key binds the authenticated principal, trust domain, complete contract ID/version/method and application key. The actual authenticated backend supplies tenant isolation. Anonymous callers are rejected. Canonical business input hashing includes ordered arguments, including the key, and excludes trace carriers, deadlines, physical attempts and selected targets. Reusing a key with changed input produces CONFLICT. A retained expired key produces EXPIRED and never becomes fresh work. Replays do not cross principals or trust domains.

Only an acquired native external claim enters the application body. A duplicate in progress, lost claim response, unavailable backend or unresolved prior effect cannot enter the body again. The first successful response and all replays materialize the authoritative stored canonical result frame; they do not retain the application's mutable return object. Completed results replay from the native journal. This protects body entry; transport decoding and explicitly registered pure codec functions execute before the claim and may execute on replay. It is not a generic exactly-once or external transaction guarantee.

The finalizer runs after actual tracked USER work settles and USER submission seals. It records the logical result and same-partition protected CAS set atomically under the acquired claim fence. `ResourceBindingFactory.deduplicationContext()` registers a provider-only `ManagedDeduplicationContext` resource, normally named `deduplication`. Its `compareAndSet` stages intents, not successful writes. It accepts at most64 distinct keys and256KiB of modified-UTF data. Each key has at most128 characters, each value16384, neither permits NUL, and expected versions are nonnegative. A retained context cannot stage from another invocation, a host codec/finalizer callback or after USER settlement. CAS conflicts publish neither the result nor earlier effects in the batch.

Only settled normalized INVALID_ARGUMENT, NOT_FOUND, PERMISSION_DENIED and UNAUTHENTICATED method errors are cached as ERROR. Error frames contain a fixed code and constant safe message; application messages, details and causes are not persisted. ERROR means a known returned method error, not proof that no external effect happened. All staged CAS intents are discarded on failure. Unclassified exceptions, codec/result overflow, cancellation, deadline and uncertain completion remain UNKNOWN. Ordinary workers receive no reconciliation capability; native administrative reconciliation remains separately authorized.

A positive original invocation budget is required to start durable completion, including protected effects. An expired caller budget is never replaced with a cleanup budget to commit effects. The separate cleanup budget permits only a best-effort UNKNOWN marker; an already unresolved external claim is still publicly unknown if that marker cannot commit. A completion begun in budget may commit after reply uncertainty, as specified by D12. Outer post-audit failure does not undo an already stored outcome. Trusted status diagnostics are carried through `InvocationResult`, never accepted from application exception details.

`ManagedPayloadCodec` uses explicit schema descriptors and a version-one bounded deterministic frame. It supports data-only fixed scalar types, explicit enums, byte arrays, supported lists/maps and registered schemas; it rejects references, exceptions, callbacks and control capabilities. Maps are sorted, strings are lossless UTF-16, and the full tree validates before a registered decoder factory is invoked. Limits are16 levels,1024 nodes and at most12288 frame bytes, fitting the native16384-character Base64 field. The host-provided codec and schema functions must be thread safe and side-effect free. No Java object serialization or wire-selected class loading is used.

Retention is finite: positive whole milliseconds up to one day; cleanup is positive whole milliseconds up to30seconds, default two seconds. Native D12 limits still apply, including10000 retained request slots and a16MiB retained-state budget. Expiry does not garbage-collect/reuse identities or reset capacity. OVERLOADED, CONFLICT, EXPIRED and UNKNOWN are explicit results, never reasons to create a new logical identity or silently switch to another partition.

The executable qualification is in `ManagedDeduplicationPolicyTest`, `ManagedPayloadCodecTest`, `ResourceBindingFactoryTest` and `ManagedDeduplicationProcessIT`. The process tests compile a real annotated application through `J7mProcessor`, load its generated component index into `ManagedContainer`, inject the provider capability and invoke the generated `ManagedHostAdapter` within the production lifetime/policy SPI. Three separate voter JVMs serve authenticated loopback TCP against real local disk. They verify100 concurrent duplicates, input conflicts, retention expiry, full quorum restart, immutable CAS versions, leader death after durable completion before reply, and separate frontend JVM deaths before effects, after effects and after durable result storage. The external TCP counter has no idempotency mechanism. The frontend is test-owned trusted host composition; this qualification does not claim signed ApplicationManager deployment or production TLS for that fixture. Combined deployment qualification belongs to A-P17.

Rollback before adoption removes additive annotations/host registrations. After adoption preserve execution journals, snapshots and retained identities; removing an adapter must not erase evidence or make old keys eligible for execution. These adapters do not modify native D12 storage formats.
