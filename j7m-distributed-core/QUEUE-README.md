# Replikované fronty a skupiny konzumentů

`ReplicatedQueue` používá `PartitionEndpoint` a obnovuje trasu při `MOVED`/`FROZEN` se stejným request ID. Produkční resolver musí číst quorum topology; `RoutedPartitionEndpoint` umožňuje sdílet tuto cestu s mapovými zdroji. `QueueStateMachine` se hostuje výhradně uvnitř `PartitionStateMachine`; přímé vystavení delegáta obchází ownership fencing a není podporováno.

Každá pojmenovaná fronta tvoří FIFO partition: současně existuje nejvýše jedno platné doručení. `send` a atomický `sendBatch` uchovají stabilní `messageId`; odlišný payload nebo delivery limit stejného ID vrací `MESSAGE_CONFLICT`. `claim` vydá ID, base64 payload, pořadí, receipt a číslo pokusu. `ack`/`nack` vyžadují přesnou generaci skupiny, přiřazeného aktivního člena a receipt. Nack či uplynutí visibility lease dovolí nové doručení; limit pokusů přesune zprávu do DLQ. Heartbeat člena neprodlužuje visibility lease zprávy.

Členové jsou seřazeni podle ID a fronta je přiřazena pomocí `floorMod(queue.hashCode(), members.size())`. Join nového člena, expirace členství a explicitní rebalance zvýší trvalou generaci. Staré generace nemohou potvrdit zprávu. Generace, živá doručení, ACK tombstones, výsledky požadavků i event journal jsou součástí přenášeného snapshotu. Interní `Q_TIME` nevyužívá retenční sloty klientských požadavků ani neprodukuje události. Před časově citlivým příkazem host připojí quorum potvrzený čas z `MeasuredClockHealth`; nejisté hodiny operaci odmítnou.

Zpracování je at-least-once. Potvrzení zprávy neprovádí automatickou transakci s externími vedlejšími účinky. Při neznámém výsledku klient opakuje stejný příkaz a request ID; opětovné použití identity s jiným příkazem se odmítá před logem. `sendBatch` přijme maximálně 256 zpráv a 131072 bajtů příkazu (limit partition transportu), atomicky; každá zpráva má samostatnou identifikovatelnou událost.

Limity verze 1: 100000 zpráv včetně ACK/DLQ tombstones, 100000 výsledků požadavků, 32 MiB base64 payloadů a 32 MiB uložených příkazů, 1024 front, 4096 skupin, 1024 členů na skupinu, 32768 bajtů payloadu zprávy a identifikátory maximálně 512 znaků. Vyčerpání kapacity vrací explicitní `OVERLOADED`; identity se tiše nemažou. Journal uchovává nejvýše 10000 událostí a 16 MiB payloadů, přičemž cursor expirace je explicitní podle kontraktu D-P09. `deadLetters` vrátí prvních nejvýše 256 identit; správa či mazání DLQ není v tomto API implementováno. Query assignment je omezen maximálním počtem front. Generický transport dále omezuje rámy, deadline a autorizované tenant scope.

Rollback před nasazením: odstranit aditivní queue soubory a jejich testy; ostatní zdroje mohou zůstat. Po přijetí queue zápisů zastavit všechny writery a obnovit celý konsistentní předchozí snapshot celé skupiny i topology; downgrade pouze části metadat není bezpečný. Snapshot verze 1 při neznámé verzi, poškození nebo porušení invariantů odmítne instalaci a ponechá původní stav. Bezpečnější následná změna formátu je dopředná migrace.

Testy: `QueueStateMachineTest`, `ReplicatedQueueTest`, `ReplicatedQueueProcessIT` a `QueueMigrationIT` ověřují deterministické operace, hranice, autorizační a časová odmítnutí, skutečné procesy a přenos úplných metadat. Finální naměřené výsledky a nezávislé V jsou vedeny v implementačním záznamu INBOX; samotná existence testu neznamená splnění gate.

Procesový zátěžový test používá heartbeat 5 ms a election timeout 500 ms; deadline operace zůstává 10 s a obnova quorum 30 s. Plán D-P10 neurčuje throughput SLO. Časově citlivý claim/ack před příkazem potvrzuje logický čas; heartbeat 70 ms záměrně dávkuje příkazy a nezajišťuje nízkou latenci sériové FIFO fronty. Produkční plánovač replikace se kvůli testu nemění.
